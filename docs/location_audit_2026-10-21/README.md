# Location audit — 21 October 2026

The audit inventories all 2,222 configured companies and reviews the 606,363 open records in the initial snapshot. It separately checks 762 live employer feeds containing 140,553 postings, 10,632 public detail pages, and 13,967 targeted Workday detail endpoints. A fresh source check is distinct from a stored-record review: companies without a fresh probe are not marked as source-verified passes.

Confirmed missing locations affected Spotify, Rivian, JPMorgan Chase, Oracle, Honeywell, BCG, Cloudflare, SoFi, SAS, Snap-on, and many others. The shared importers now retain Lever allLocations, Oracle secondary geography and work-office fields, Jobs API additional_locations/full_location, Phenom multi_location fields, iCIMS multi-place structured data, and explicit Greenhouse job-posting location metadata. Greenhouse office assignments are not treated as additional hiring cities.

Workday scans retain complete cached location lists, including resolved country labels, and expand unresolved lists independently of the description budget. Failed detail refreshes preserve existing verified locations. A requisition's primary country is no longer assigned to offices in other countries. US country/state/city labels, unresolved placeholders, and repeated country aliases are also normalized correctly.

Production repairs update only location columns and the supplied public location metadata. Each write checks job identity and verifies that all other fields remain unchanged. Job IDs, posting dates, first-seen dates, and saved-job relationships are preserved by the repair. Rows closed or changed by later scans are skipped; a fresh Workday recheck covers discrepancies observed after scheduled scans. BOA's dedicated locationString/additionalLocationsList data is protected from its older, incomplete Workday descriptors. No alert emails or job-expiry operations are triggered by these repairs.

Production repairs updated 25,435 distinct jobs across 600 companies, with 28,376 location writes across three guarded passes (some jobs were refined more than once). The complete test suite passes 217 tests. All 22 live UI checks pass without JavaScript errors. Final production counts, application-file hashes, and live UI checks are recorded in verification.json. The live location checks exercise company/location filters and job drawers; they do not change the existing keyword-intent matching behavior.

- [All-company inventory](all_companies.csv): initial open/missing/multiple-location counts, fresh-feed status, and detail-check coverage for every configured company.
- [Reviewed location proposals](location_repairs.csv): initial snapshot locations and reviewed replacement locations. This is an audit/proposal ledger, not a claim that every proposal was applied: later closures, identity changes, and newer scan results can make an update unnecessary or unsafe.
- [Source verification gaps](source_gaps.csv): 13 failed/moved sources and two incomplete Phenom lists. Empty feeds and sources without published location data are not invented as successful hiring/location checks.
- [Verification results](verification.json): actual applied counts, skipped rows, preserved identities/dates, test results, and public-site checks.

Fresh source verification remains incomplete for the sources in source_gaps.csv. Some detail pages also block requests, omit structured location data, or have closed since the snapshot. The source and detail coverage counts in summary.json keep these outcomes separate from confirmed repairs. A final comparison also rechecked 14 rows changed by later scans: nine match current employer data, four remain unverified, and one has a primary-label formatting difference with the secondary cities retained. These observations are recorded in post_scan_differences.json. The audit does not certify that every company's website or every individual posting is issue-free.

Read-only source checks can be repeated with scripts/audit_company_locations.py. scripts/build_location_audit_report.py builds the inventory and review proposals from the ignored runtime evidence directory. scripts/repair_job_locations.py previews proposals by default; applying reviewed proposals requires --apply and a private backup directory. Databases, account data, full backups, and runtime source payloads are excluded from Git.
